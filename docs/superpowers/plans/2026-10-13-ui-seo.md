# gsinvest.com.tw UI 優化與 SEO/GEO 實作計畫

- 對應 spec：`docs/superpowers/specs/2026-10-13-ui-seo-design.md`
- 分支：`feat/ui-seo`
- 以下行號指 `app.prod.js` / `index.html` 於 commit `feda0ac` 的版本，搬移後以函式名稱為準。

## 實作前發現（已反映到 spec）

1. **手機選單壞掉**：≤1024px 時 `.nav-links` 隱藏、顯示 `.nav-burger`，但 burger 沒有任何 onClick（`Nav`，約 1835 行）。手機上目前無法從選單跳頁。→ 列入第 4 組修正。
2. **Intro 是死碼**：`Intro`（約 1882 行）沒有被渲染；使用者看到的「LOADING」是 `index.html` 的 `#boot-splash`。
3. **頁尾沒有被渲染**：`I18N.*.footer` 的 explore/legal/connect 連結只存在於字串中，畫面上沒有死連結；`disclaimer` 也從未顯示。→ 刪除未用字串，並在聯絡區底部的 `contact-footer` 改為 `<footer>` 顯示 disclaimer。
4. **語意結構大致已正確**：Hero 已有唯一 `<h1>`，各區塊已有 `<h2>`，Nav 已用 `<a href="#id">`。第 2 組只需補 `<footer>`、圖片 alt 與聯絡連結。
5. **圖片是 CSS 背景**：`Space` 用 `div.space-img` + `backgroundImage`，沒有 alt。→ 改為 `<picture><img>`。
6. **圖片路徑為相對路徑**（`data/images/...`），放到 `/en/` 底下會 404。→ 改為絕對路徑。
7. **語言沒有持久化**：`useTweaks` 只是 `useState` 加 `postMessage` 給設計工具的 parent frame，重新整理即回到繁中。
8. **Hero CTA 的 `data-pageto`** 未被使用且值錯誤（聯絡寫成 6）；實際由 `hashchange` 處理。→ 移除該屬性。
9. `ThreePillar` 只在第 4 頁 active 時掛載，已無背景耗能問題；需處理的是常駐的 `ThreeHero`。

## 共通約定

- 預渲染要求 **DOM 與版面模式無關**：桌機整頁/手機捲動的差異只能由 CSS 與事件處理決定，不可用 JS 條件渲染不同的元素結構。
- 整頁模式斷點採 `(min-width: 1025px)`，與既有 `max-width: 1024px` 查詢對齊。
- 所有資源路徑使用絕對路徑（`/app.js`、`/vendor/...`、`/data/images/...`）。
- 每個 task 結束都要能 `npm run build` 成功並通過當時已存在的測試。
- npm scripts：`build`、`serve`（`node build/serve.mjs dist 4173`）、`test`（Playwright）、`lhci`。

## 第 1 組：目錄重整與建置流程

### Task 1：搬移檔案與初始化 npm

1. `git mv index.html src/index.html`、`app.prod.js`、`favicon.svg`、`data/` 移入 `src/`；`CNAME`、`.nojekyll` 移入 `src/static/`。
2. 新增 `package.json`（`"type": "module"`、`"private": true`），devDependencies 鎖定版本：`react@18.3.1`、`react-dom@18.3.1`、`three@0.128.0`、`esbuild`、`sharp`、`@playwright/test`、`@lhci/cli`。
3. `.gitignore`：`node_modules/`、`dist/`、`test-results/`、`.lighthouseci/`。
4. **驗證**：`npm ci` 成功；`git status` 僅有 rename 與新檔。

### Task 2：建置腳本 `build/build.mjs` 與本機伺服器

1. `build/serve.mjs`：以 Node `http` 提供靜態檔，支援 `/en/` → `/en/index.html`，供 prerender、測試與 Lighthouse 共用。
2. `build/build.mjs` 依序：
   - 清空並建立 `dist/`；複製 `src/static/*`、`src/favicon.svg`、`src/data/`。
   - 從 `node_modules` 複製 `react.production.min.js`、`react-dom.production.min.js`、`three.min.js` 至 `dist/vendor/`。
   - esbuild 壓縮 `src/app.prod.js` → `dist/app.js`（`minify: true`、`target: es2019`、不打包）。
   - 讀 `src/index.html`，把 unpkg/cdnjs 的 `<script>` 換成 `/vendor/...`，把 `app.prod.js` 換成 `/app.js`，輸出 `dist/index.html` 與 `dist/en/index.html`。
3. **驗證**：`npm run build && npm run serve`，在瀏覽器面板開 `http://localhost:4173/`，畫面與正式站一致，console 無錯誤。

### Task 3：語言改由網址決定、移除 Tweaks 與死碼

1. 先寫 `tests/locale.spec.ts`（預期失敗）：
   - 開 `/` → `html[lang=zh-Hant]`、Hero 為中文。
   - 開 `/en/` → `html[lang=en]`、Hero 為英文。
   - 在 `/` 點語言切換 → 網址變 `/en/`（hash 保留），按上一頁回到 `/`。
2. `app.prod.js`：
   - 刪除整個 `tweaks-panel.jsx` 區塊、`TweaksPanel` 的渲染、`TWEAK_DEFAULTS` 與 `Intro` 函式；`goldColor`、`rotationSpeed`、`particleDensity` 改為常數。
   - `locale` 初始值：`location.pathname.startsWith("/en") ? "en" : "zh"`。
   - `setLocale` 改為切換並 `history.pushState`（`/` ↔ `/en/`，附上目前 hash）；監聽 `popstate` 同步。
   - I18N 內圖片路徑改為 `/data/images/...`。
3. **驗證**：`npm test` 中 locale 測試通過。

### Task 4：預先渲染 `build/prerender.mjs`

1. 先寫 `tests/prerender.spec.ts`（讀檔，不開瀏覽器）：
   - `dist/index.html` 與 `dist/en/index.html` 的 `#root` 內有 8 個 `section[id]`（top、about、services、philosophy、team、space、milestones、contact）與 1 個 `<h1>`。
   - 不含 `<canvas>`、`boot-splash`、`LOADING`。
2. `app.prod.js`：`App` 首次 `useEffect` 中設 `window.__appReady = true`；若 `#root` 有 `data-prerendered` 屬性，略過 `first-load` 進場動畫，避免接手時內容閃一次。
3. `src/index.html`：刪除 `#boot-splash` 的 HTML 與 CSS，以及移除它的 JS。
4. `prerender.mjs`：啟動 `serve.mjs` → Playwright Chromium（viewport 1440×900）依序載入 `/`、`/en/` → `waitForFunction(() => window.__appReady)` → 移除 `canvas` → 取 `#root.innerHTML` → 寫回對應 `dist/*.html` 的 `#root`，並加上 `data-prerendered`。
5. `build.mjs` 最後呼叫 prerender；`npm run build` 一次完成。
6. **驗證**：prerender 測試通過；在瀏覽器面板停用 JavaScript 開 `/` 與 `/en/`，8 個區塊內容都可見。

### Task 5：GitHub Actions `.github/workflows/pages.yml`

1. `pull_request`：`npm ci` → `npx playwright install --with-deps chromium` → `npm run build` → `npm test` → `npm run lhci`。
2. `push` 到 `main`：同上建置與測試，再 `actions/upload-pages-artifact`（`dist/`）→ `actions/deploy-pages`。權限 `pages: write`、`id-token: write`。
3. 此時尚未切換 Pages 來源，`deploy` job 會失敗或略過；切換在上線步驟進行。
4. **驗證**：push 分支並開 draft PR，CI 綠燈（lhci 門檻在第 3 組完成前先設為 warn）。

**commit**：`Restructure site into src/ with build and prerender pipeline`

## 第 2 組：SEO 與 GEO

### Task 6：`build/seo.config.mjs` 與 `<head>`

1. 先擴充 `tests/prerender.spec.ts`：兩份 HTML 各有 `title`、`meta[name=description]`、`link[rel=canonical]`、3 個 `link[rel=alternate][hreflang]`、`og:title`/`og:description`/`og:image`/`og:url`、`twitter:card`；JSON-LD 可 `JSON.parse`，其 `telephone`、`email`、`address.streetAddress` 與 `app.prod.js` 的 `contact.info` 一致。
2. `seo.config.mjs` 匯出 `{ siteUrl, locales: { zh: {...}, en: {...} }, organization }`，內容依 spec 2.1、2.2；description 從 hero 與 about 文案濃縮。
3. `prerender.mjs` 依 locale 替換 `<title>`、`<html lang>`，並注入上述標籤與 JSON-LD。
4. **驗證**：測試通過；Google 複合式搜尋結果測試的「程式碼」模式貼上 `dist/index.html` 無錯誤。

### Task 7：OG 分享圖

1. `build/og-image.mjs`：以 Playwright 截一張 1200×630 的 HTML（黑底、`favicon.svg` 的 GS 標誌、中英公司名、標語），輸出 `src/static/og-image.png`。
2. 執行一次並 commit 產出圖片（不在 CI 重新產生）。
3. **驗證**：圖檔 < 300 KB，用瀏覽器面板開啟目視確認。

### Task 8：`robots.txt`、`sitemap.xml`、`llms.txt`

1. 由 `prerender.mjs` 依 `seo.config.mjs` 產生，內容依 spec 2.4；sitemap 含 `/` 與 `/en/`，各帶 `xhtml:link` hreflang 與 `lastmod`（建置日期）。
2. 擴充測試：三個檔案存在；`robots.txt` 含 `Sitemap:` 行；sitemap 是合法 XML。

### Task 9：語意與內容修整

1. 先寫 `tests/links.spec.ts`：兩份 HTML 中所有 `a[href]` 不為空或 `#`；所有 `href="#x"` 都對得到 `id="x"`；`tel:`、`mailto:` 各至少一個。
2. `Contact`：Phone → `<a href="tel:+886422991928">`；Email → `mailto:`；Address → Google 地圖搜尋連結（`target="_blank" rel="noopener"`）。
3. `contact-footer` 改為 `<footer>`，加入 `t.disclaimer`。
4. 刪除 I18N 中未使用的 `footer.explore*`、`legal*`、`connect*` 字串與聯絡表單 `form` 字串。
5. 移除 Hero CTA 的 `data-pageto`。
6. **驗證**：links 測試通過。

**commit**：`Add SEO metadata, structured data, and GEO files`

## 第 3 組：效能

### Task 10：響應式圖片

1. `build/images.mjs`（由 `build.mjs` 呼叫）：對 `src/data/images/*.png` 以 sharp 輸出 `{name}-{640,1024,1600}.{avif,webp}`，並保留一份 1600 寬 JPEG 作為後備；結果快取在 `node_modules/.cache/images`，原圖未變就略過。
2. `Space`：`div.space-img` 改為 `<picture>`（AVIF、WebP 的 `<source srcset sizes>` + JPEG `<img>`），`<img>` 帶 `alt`（使用 `it.title`）、`width`、`height`、`loading="lazy"`、`decoding="async"`；CSS 以 `object-fit: cover` 維持原外觀。
3. CSS：在整頁模式的 media query 內加 `.page:not(.active) .space-fig picture { display: none; }`。
4. 擴充測試：桌機進站後網路請求中沒有 `office_build`、`workspace` 的任何格式；切到第 6 頁後才出現。
5. **驗證**：測試通過；目視第 6 頁與改版前一致。

### Task 11：Three.js 延後初始化與降載

1. `ThreeHero`：在 `threeready` 後再以 `requestIdleCallback`（無則 `setTimeout 200`）初始化。
2. `matchMedia("(max-width: 1024px)")` 時：`setPixelRatio(Math.min(dpr, 1.5))`、`particleCount` 減半。
3. `document.visibilitychange` 隱藏時暫停 render loop。
4. `prefers-reduced-motion: reduce` 時不初始化 `ThreeHero` 與 `ThreePillar`，`#three-bg` 顯示靜態 CSS 漸層。
5. **驗證**：在瀏覽器面板以 Performance 時間軸確認首屏繪製早於 WebGL 初始化；手機模擬下捲動順暢。

### Task 12：字型字重精簡

1. `build/font-audit.mjs`：Playwright 開 `/` 與 `/en/`，在桌機與手機 viewport 收集所有可見元素的 `fontFamily` 主字族與 `fontWeight` 組合。
2. 依結果改寫 `src/index.html` 的 Google Fonts URL，只保留用到的字重。
3. **驗證**：重跑 audit，沒有元素落到被移除的字重；目視比對無明顯差異。

### Task 13：開啟 Lighthouse 門檻

1. `lighthouserc.json`：URL 為 `/`、`/en/`，`numberOfRuns: 3`，preset 手機；assert 依 spec 第 3 節，含 `total-byte-weight` ≤ 614400。
2. 在 `pages.yml` 把 lhci 從 warn 改為 error。
3. **驗證**：本機 `npm run lhci` 全部通過；未通過則回頭調整後再進下一組。

**commit**：`Optimize images, Three.js startup, and font loading`

## 第 4 組：手機版與視覺

### Task 14：雙模式換頁（桌機整頁、手機捲動）

1. 先寫 `tests/layout.spec.ts`：
   - 桌機 1440×900：`ArrowDown` 換頁、網址 hash 變 `#about`；開 `/#team` 直接顯示團隊頁。
   - 手機 375×812：`document.scrollingElement` 可以捲動；8 個區塊依序排列；捲到聯絡區時 hash 為 `#contact`；`scrollWidth <= innerWidth`；`.pager` 與 `.page-counter` 不可見。
2. CSS：把「PAGED MODE」整段（`html, body { height:100% }`、`body { overflow:hidden }`、`.page-shell`、`.page` 絕對定位與透明度、轉場）包進 `@media (min-width: 1025px)`；≤1024px 時 `.page` 為一般區塊流、`.pager`、`.page-counter` 設為 `display:none`。
3. `App`：以 `useMediaQuery("(min-width: 1025px)")` 取得 `paged`。
   - `paged` 為 true：維持現有 wheel/key/touch 處理；`goTo` 後 `history.replaceState` 更新 hash。
   - `paged` 為 false：不掛 wheel/touch/key 處理；`goTo(i)` 改為 `scrollIntoView`；以 `IntersectionObserver` 更新 `currentPage` 與 hash。
   - `aria-hidden` 僅在 `paged` 時套用於非當前頁。
4. **驗證**：layout 測試通過；在瀏覽器面板分別以桌機與手機實際操作。

### Task 15：手機選單與 Header

1. 擴充 layout 測試：手機點 burger 開啟選單、`aria-expanded="true"`、點「聯絡我們」捲到聯絡區並關閉選單；`Esc` 可關閉。
2. `Nav`：burger 加 `aria-expanded`、`aria-controls`，控制全螢幕選單（7 個連結 + 語言切換）；開啟時鎖背景捲動。
3. ≤768px：logo 文字只顯示「創世紀」/「Genesis」，隱藏「GS · EST. 2025」；語言切換改為單一按鈕（中文頁顯示「EN」，英文頁顯示「中」）。
4. **驗證**：測試通過；375px 下 header 單行不換行。

### Task 16：版面細修

1. 聯絡頁橫向溢出：以瀏覽器面板找出超出 `innerWidth` 的元素並修正（預期為 `.lead` 或 `.contact-info-block` 的寬度設定）。
2. 發展藍圖：≤600px 時 `.timeline-h` 改單欄。
3. 手機 `#three-bg`：物件縮小、`opacity` 降至約 0.35、位置上移，不與內文重疊。
4. `--ink-mute` 提亮，使與 `--bg` 對比 ≥ 4.5:1（以計算確認數值）。
5. 觸控目標：nav 連結、語言切換、burger、聯絡連結至少 44×44px。
6. `prefers-reduced-motion`：關閉 `.page` 轉場與 `page-in` 動畫。
7. **驗證**：Lighthouse Accessibility ≥ 95；手機 8 個區塊逐一截圖檢查。

**commit**：`Improve mobile layout, navigation, and accessibility`
